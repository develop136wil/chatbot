# 피드백 복구 및 구형 답변 캐시 정리 (2026-09-21)

## 피드백

- 성공 확인 전에는 입력창/선택 사유/의견을 삭제하지 않는다.
- 전송 중 해당 피드백 폼의 입력과 버튼을 잠근다. 중복 함수 호출도 차단한다.
- 실패 시 기존 활성/비활성 상태를 복원하고 4개 언어로 안내한다.
- 의견 사유를 바꿔도 작성하던 코멘트를 새 입력창에 전달한다.
- 오프라인에서는 전송하지 않는다. 자동 재전송하지 않는다.
- 15초 후 fetch를 취소하며 타이머를 정리한다.
- 429 Retry-After 동안 같은 폼의 수동 재전송도 차단한다.
- 저장 성공 후 동일 폼에서 다시 호출해도 중복 전송하지 않는다.
- 실패 후 폼을 다시 열어도 대기 제한과 상태 안내를 유지한다.
- 의견은 현재 DOM에만 보존하며 localStorage나 별도 DB에 기록하지 않는다.

한계: 저장 성공 응답이 유실된 경우, 서버 저장 여부를 클라이언트가 확정할 수 없다.
따라서 재전송 시 중복 저장될 수 있다고 명시한다. Notion 저장의 멱등성이나
페이지 새로고침 후 초안 복구를 구현한 것은 아니다.
클라이언트 시간 초과는 이미 진행 중인 서버 저장을 취소한다고 보장하지 않는다.

## 답변 캐시

main.py에서 chatbot:main_answers 해시를 질문만으로 조회하던 구형 경로를 제거했다.
언어, 대화 문맥, 문서 변경 버전을 검사하는 기존 Supabase 응답 캐시는 유지한다.

- KO/EN/VI/ZH 요청에서 구형 데이터가 있어도 읽지 않는다.
- 대화 후속 질문도 구형 캐시로 우회하지 않는다.
- 적합한 Supabase 캐시가 있으면 기존처럼 AI 의도 분석/Redis 큐보다 먼저 반환한다.
- 캐시가 없으면 기존 검색/작업 큐를 실행한다. 구형 데이터에만 있던 답변은
  다시 생성될 수 있으며 초기 캐시 미스에 따른 AI 사용이 발생할 수 있다.
- 현재 Vercel Production 직접 실행은 원래 구형 경로를 사용하지 않았다.
- Redis 작업 결과 저장/조회, 추출·랭킹 등 다른 캐시는 변경하지 않는다.
- 실제 Redis 데이터를 삭제하지 않았다. 기존 관리자 정리 기능은 남겨두었다.
