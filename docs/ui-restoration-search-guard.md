# 기존 UI 복원 및 새 질문 보호 (2026-09-21)

## 변경

- 표시 이름을 도봉구 영유아 복지정보자료집으로 통일한다.
  시작 화면, 한국어 제목, 문서 제목, 설치 앱 이름을 맞춘다.
- 언어 선택을 오른쪽 국기 버튼으로 복원한다. 기기에 따라 국기 이모지가
  KR/US 같은 문자로 보이지 않도록 로컬 SVG 4개를 사용한다.
  언어별 aria-label, 선택 상태, 키보드 포커스는 유지한다.
- 제목의 글라스 효과를 덮던 불투명 부모 배경을 반투명/블러로 바꾼다.
  국기가 답변을 가리지 않도록 오른쪽 공간을 확보한다.
  입력창·추천 질문·하단 이동 버튼의 기존 글라스 효과는 유지한다.
- 대기 중 각 언어의 일상 육아 팁 8개를 AI 호출 없이 표시한다.
  첫 팁은 무작위, 이후 7초마다 직전 팁을 제외하고 선택한다.
  성공·실패·취소 시 타이머를 정리한다.
  기존 팁의 건강 효과 단정은 복원하지 않고 일상 놀이·대화 문구로 구성했다.
- 안내 문단 사이 빈 줄과 사용자 질문의 줄바꿈을 보존한다.
- 시작 화면은 초기 로드 때만 표시하고 JS 준비 후 바로 제거한다.
  최소 대기 시간을 강제하지 않는다. JS 실패 시에도 CSS가 3초 후 숨기며
  포인터 입력을 막지 않는다. 동작 줄이기 설정에서는 로고 등장 애니메이션을 끈다.
- 사용자 요청에 따라 라이트 모드만 유지한다.

## 새 질문과 더 보기

action=more 또는 명시적인 더 보기 문구만 이전 결과를 이어서 표시한다.
AI가 양육수당 지원 같은 새 질문을 show_more로 잘못 분류하더라도
더 보기로 보내지 않고 검색 경로를 실행한다.
이때 [Intent Guard]와 요청 ID를 기록한다.

한계: 정확한 명령 목록에 없는 자유로운 더 보기 표현은 새 검색으로 처리할 수 있다.
더 보기 버튼은 영향을 받지 않으며 명시적인 더 보기 문구는 AI 호출 없이 처리한다.

## 검색 0건 진단

기존 검색 임계값, 모델, 임베딩, 랭킹, 캐시 정책은 바꾸지 않는다.

- [Search Rows]: 카테고리/전체 RPC 단계별 행 수와 기존 임계값.
- 전체 검색까지 0건이면 동일 검색 클라이언트로 site_pages의 HEAD 정확 개수 조회.
  추가 AI 요청은 없으며 진단 대기는 최대 3초다.
- [Search Diagnostic]: 요청 ID, 배포 환경, 프로젝트 호스트, 임베딩 차원,
  조회 가능한 문서 수 또는 오류 종류. 비밀 키·질문·문서 내용은 포함하지 않는다.
- 조회 가능한 문서가 0개이거나 확인에 실패하면 정상적인 '관련 정보 없음'과
  구분하여 search_unavailable 오류를 반환한다.
- 조회 가능한 문서가 있는데 RPC만 0건이면 기존 빈 결과를 유지한다.
  임의의 낮은 임계값으로 관련 없는 문서를 돌려주지 않는다.

HEAD 개수 0은 실제 빈 DB와 권한에 의해 보이지 않는 DB를 구분하지 못한다.
개수가 있어도 임베딩 상태·RPC 정의·필터 정확성이 입증되는 것은 아니다.
타임아웃은 대기를 중단하지만 이미 시작한 동기 HTTP 스레드 취소를 보장하지 않는다.

## 검증 및 남은 확인

- 로컬 오프라인 Python 114개 + JavaScript 90개 통과.
- CI의 실제 Redis 통합 테스트 6개는 별도 확인한다.
- 새 국기 파일을 포함한 HTML/CSS/manifest 로컬 자산 HTTP 200 검사.
- 실제 AI·Notion·Supabase를 호출하지 않은 회귀 테스트다.
- 브라우저 화면 확인 도구가 sandbox 초기화 오류로 실패했다.
  실제 모바일 레이아웃, 블러 효과, 운영 검색 정상 여부는 별도 확인이 필요하다.
- 최초 검색 0건의 실서비스 원인은 아직 확정하지 않았다.
  새 Preview에서 같은 질문을 보내고 위 진단 로그를 확인해야 한다.

새 SQL, 환경변수, 의존성, 운영 DB 변경은 없다.
운영 main 브랜치에는 병합하지 않는다.
