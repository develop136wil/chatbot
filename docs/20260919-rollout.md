# 2026-09-19 안정성 개선 및 배포 안내

## 현재 상태

로컬 코드 개선 및 회귀 테스트 완료. **커밋·푸시·운영 배포·운영 SQL 실행은 아직 하지 않았습니다.**
새 코드에는 운영 DB의 새 함수/트리거가 필요합니다. 기존 서버용 키를 교체할 필요는 없습니다.

기준 커밋: 2b4eddb. 개선 전 감사: [REPORT](../audit/2026-09-19/REPORT.md).
감사 스크립트 checks.py는 예전 결함 재현용이며 현재 정상 판정 테스트가 아닙니다.
현재 회귀 테스트는 tests/ 아래 파일입니다.

## 수정한 내용

- 검색 실패와 실제 0건 분리. 장애/빈 결과/랭킹 대체 결과는 장기 캐시 저장하지 않음.
- 실제 검색 범위와 검색 전 버전을 캐시에 기록. 저장 전 버전이 바뀌면 생략.
- 문서 쓰기와 캐시 범위 갱신을 같은 DB 트랜잭션에서 실행. 삭제와 카테고리 이동도 반영.
- 캐시 v3로 변경. 기존 v2 캐시는 읽지 않으므로 첫 요청은 다시 검색될 수 있음.
- 직전 질문 반복 시 캐시 재사용 유지. 문맥 의존 답변을 공유 캐시에 저장하지 않음.
- 연령·대상 특성·후속 질문의 독립 검색문을 워커까지 전달. 연령 필터를 모든 검색 경로에 적용.
  대상 특성은 정확 일치 우선 정렬이며 모든 자격 요건을 자동 판정하는 기능은 아님.
- 의도 분석 구조화 JSON 및 잘못된 category/age/null 정규화, 실패 시 규칙 대체.
- 무료 모드에서 Supabase 공용 일일 예산 적용. 조회 실패/한도 도달 시 비AI 키워드 검색.
  캐시/명시적 더 보기/초기화는 AI 예산을 예약하지 않음.
- 임베딩 장애도 비AI 검색으로 대체. 대체 답변에는 제한 안내를 표시하고 장기 저장하지 않음.
- 작업별 출력 상한 분리, 잘린 AI 응답 거부, 중첩 재시도 제거, HTTP/작업 시간 제한.
- 미완료 언어만 번역 보충. 번역만 보완하는 문서는 임베딩 재사용.
- 인덱서 실패/번역 보류/예산 보류/삭제 실패는 실패 종료. 성공한 쓰기는 다른 문서 실패와 독립적으로 캐시 무효화.
- Notion 페이지네이션 검증, DB 상태 페이지 순회, 원본 전체 0건일 때 전체 삭제 차단.
- 인덱서 동시 실행 방지·실행 시간 상한, DB ID 공통 환경변수 적용.
- 4개 언어 피드백·카드 버튼, 더 보기 버튼, 삭제된 문서 건너뛰기, 직접/큐 응답 공통 렌더링.
- 피드백 저장 실패를 성공으로 표시하지 않음. Notion 저장의 비동기 분리 및 시간 제한.
- 초기화 시 실제 대화내역·문서 ID·커서 초기화. 중복 제출과 응답 중 언어 전환 방지.
- 대화내역/문서 ID 검증, HTTPS 세션 쿠키, 큐 결과 세션 소유권 검사.
- 관리자 헤더 인증, Supabase 응답 캐시 삭제 지원, /health에 liveness와 revision 명시.
- 캐시 Saved/Miss 원인 로그 및 배포 버전 마커 2026.09.19-safety-v3 추가.

기존 Gemini 검색/임베딩 모델, 768차원, 검색 임계값(카테고리 0.45 / 전체 0.4)은 유지했습니다.
프롬프트·오류 처리·연령 적용은 변경되었으므로 실제 답변 품질 비교는 별도로 필요합니다.

## 필수 배포 순서

1. 테스트 브랜치의 Regression Tests 결과를 먼저 확인합니다.
   Python 3.11 + Node 24 + 격리 PostgreSQL 17 검증을 추가했습니다.
   tests/database_regression.sql은 권한, 예산 상한, 쓰기/무효화 롤백을 검사합니다.
   tests/database_concurrency.py는 24~30개 동시 연결에서 전체/사용자/혼합 한도를 검사합니다.
   **이 테스트 SQL은 운영 DB 실행 금지**입니다. 임시 역할/테이블을 생성하는 테스트 전용 파일입니다.
2. Vercel SUPABASE_URL과 실제 프로젝트 reference 일치를 확인합니다.
   이전 확인 기준 reference는 vlxxxpqyvrvcwffrpvid입니다. 기존 서버 키는 유지합니다.
3. 해당 프로젝트 SQL Editor에서 [20260919_runtime_safety.sql](../supabase/20260919_runtime_safety.sql)을 실행합니다.
   기존 [response_cache](../supabase/20260730_response_cache.sql)와
   [response_cache_scopes](../supabase/20260730_response_cache_scopes.sql)가 적용되어 있어야 합니다.
   새 SQL은 문서/임베딩/기존 캐시를 삭제하지 않습니다.
   이후 예산 함수는 자체 사용량 원장의 7일 초과 행만 정리합니다.
4. 아래 읽기 전용 쿼리에서 ready=true 및 테이블 이름을 확인합니다.

       select public.chatbot_runtime_ready() as ready;
       select to_regclass('public.chatbot_ai_daily_usage') as usage_table;

5. 테스트가 통과한 코드를 운영 배포합니다. 새 환경변수는 모두 기본값이 있으므로
   제한을 변경할 때만 추가합니다. SQL이 없으면 새 인덱서는 쓰기를 중단하고,
   무료 모드 채팅은 AI 없는 키워드 검색으로 전환합니다.
6. 아래 운영 검증까지 끝낸 뒤 운영 반영 완료로 판단합니다.

## 기본 예산과 주의점

| 설정 | 기본값 | 의미 |
|---|---:|---|
| FREE_TIER_ONLY | true | Gemini 키 순환 금지 등 무료 모드 |
| SHARED_AI_BUDGET_ENABLED | true | 서버 공용 예산 검사 |
| AI_DAILY_GLOBAL_LIMIT | 100 | 한국시간 하루 대화+인덱싱 작업 예약 합계 |
| AI_DAILY_CLIENT_LIMIT | 30 | IP 기반 HMAC 식별자의 하루 대화 예약 |
| FREE_TIER_DAILY_REQUESTS_PER_SESSION | 30 | 추가 브라우저 세션 제한 |
| FREE_TIER_MAX_OUTPUT_TOKENS | 400 | 일반 Gemini 출력 상한 |
| FREE_TIER_TRANSLATION_MAX_TOKENS | 4096 | 인덱싱 번역 출력 상한 |
| ALLOW_LIVE_TRANSLATION | false | 기본적으로 저장된 번역 사용 |
| CHAT_RESPONSE_CACHE_TTL_SECONDS | 7776000 | 보관 상한 90일, 버전 변경 시 재사용 금지 |

예산 1단위는 캐시 미적중 질문 1개 또는 변경/번역 보완 문서 1개입니다.
**AI 호출 1회나 토큰 1개가 아닙니다.** 한 작업은 여러 AI 호출을 할 수 있습니다.
예약 후 실패해도 환급하지 않습니다. 재시도로 한도를 우회하지 않기 위한 보수적 처리입니다.
인덱싱과 대화가 예산을 공유하므로 수정 문서 155개를 하루에 모두 번역한다고 보장하지 않습니다.
남은 작업은 deferred/translation_pending에 표시하고 다음 실행에서 재시도합니다.
전체 상한을 바꾸면 Vercel와 Actions 양쪽에 동일한 값을 설정하세요.

무료 플래그는 공급자의 유료 계정/결제 연결을 차단하지 않습니다.
공급자 콘솔의 무료 플랜·결제 상태는 별도 확인해야 하며 **코드만으로 0원 과금은 보장할 수 없습니다.**
분당 제한의 Vercel 메모리 대체는 인스턴스별이며, 전체 강제 상한은 DB 일일 원장입니다.
IP 기준은 공용 네트워크의 사용자가 한도를 공유할 수 있습니다.

## 배포 후 확인

- /health revision이 배포 커밋인지 확인. status=ok는 생존 확인이지 DB/AI 정상 판정이 아님.
- 독립 질문 → 캐시 Saved → 동일 질문 반복 시 Hit 및 AI 호출 없음 확인.
- 후속 질문 나이/대상 조건 유지와 문맥 의존 질문의 공용 캐시 우회 확인.
- 더 보기 중복/마지막 페이지/삭제 문서 처리 확인.
- KO/EN/VI/ZH 카드 제목·본문·버튼·피드백 및 초기화 후 history 초기화 확인.
- 모바일/다크모드 마지막 카드·버튼 가림 여부 실화면 확인.
- 피드백 실제 Notion 행 저장 확인. 503에서 성공 문구가 나오면 안 됨.
- INDEXING_SUMMARY의 failed/deferred/translation_pending=0, critical_error=false 확인.
- Notion 변경 1건 후 범위 갱신/해당 캐시 미적중 확인. 삭제 실험은 테스트 환경에서만 진행.
- 예산 소진 시험은 Preview/테스트 DB에서 진행. 운영 예산을 일부러 소진하지 말 것.
- 대표 질문별 기존/신규 답변의 정확성 비교 및 p50/p95 시간 측정.

## 검증 결과와 한계

확인 완료:

- Python 3.14 로컬 회귀 테스트 48개 전체 통과.
- Node 24 UI 로직 테스트 10개 전체 통과(모의 DOM).
- Python/JavaScript 문법 검사, 설치 환경 pip check.
- 운영 Supabase 읽기 전용 비AI 검색: KO 4건, EN/VI/ZH 각 20건 반환.
  검색어는 아동수당/child/trẻ/儿童이며 의미적 정답률 시험은 아닙니다.
- 고정 marked 15.0.12 / DOMPurify 3.2.6 CDN HTTP 200.

남은 검증:

- 2026-09-20: PGlite 0.5.8의 메모리 PostgreSQL 18.3에서 신규 SQL을 실행해 통과했습니다.
  권한/RLS, 문서·캐시 보존, 재적용, 쓰기/무효화 롤백, 순차 예산 상한, 트리거 준비 상태를 확인했습니다.
  단일 연결 엔진이므로 다중 세션 경합은 검증하지 못했습니다.
  native PostgreSQL 17 CI에 24~30개 동시 요청 검사를 추가했으며 실행 결과는 아직 없습니다.
- Python 3.11 CI와 실제 Vercel 설치 환경 테스트는 실행 전입니다.
  로컬 notion-client는 1.0이고 requirements는 >=2이므로 SDK 동일성은 보장하지 않습니다.
- 실제 AI 생성/인덱싱 쓰기/운영 SQL/운영 배포는 하지 않았습니다.
- 155개 번역 의미·자격 조건 전수 대조, 새 프롬프트 정답률, 부하·지연, 모바일 실화면 미검증.
- 종속성 전체 lock, 과거 코드/추적 node_modules 정리, 장기 운영 대시보드는 이번 변경 범위 밖입니다.
- 번역이 없을 때 한국어를 표시하는 경로는 유지. 문자열 필드 존재만으로 번역 의미의 완전성을 보장하지 않습니다.

## 롤백

문제가 있으면 이전 정상 Vercel 배포로 되돌리고 새 인덱싱을 멈춘 뒤 로그를 확인합니다.
추가 테이블/트리거는 이전 코드와 공존 가능합니다. 예전 인덱서의 수동 범위 증가와
중복 증가할 수 있지만 오래된 캐시가 재사용되는 방향은 아닙니다.
DB 데이터 삭제나 키 회전은 롤백에 필요하지 않습니다.
새 캐시는 v3이므로 이전 v2 코드와 같은 캐시를 재사용하지 않습니다.
