# SQL 없이 진행한 UI·응답 시간 개선

작성일: 2026-09-20
작업 브랜치: `codex/no-sql-ui-observability-20260920`
기준: `main / 2b4eddb`
대상 저장소: `develop136wil/chatbot`

## 범위

새 Supabase SQL, 테이블, RPC, 환경변수를 요구하지 않습니다.
이미 운영 중인 기존 검색·응답 캐시 테이블은 그대로 필요합니다.
SQL이 필요한 기존 안정화 작업은 `codex/stability-regression-20260920`에 보존했습니다.
이번 브랜치에 그 변경을 통째로 가져오지는 않았습니다.

- 중복 질문 전송 차단, 순차 결과 조회와 요청 취소 처리
- 직접 응답과 대기 작업 응답의 렌더링 통합
- 한국어·영어·베트남어·중국어의 더 보기 및 피드백 문구
- 이전 결과 ID가 있더라도 직전과 동일한 질문은 기존 공유 캐시 조회
- 더 보기 요청은 캐시 질문과 분리하고 결과가 없으면 AI 없이 안내
- 초기화 응답이 실제 대화 내역과 결과 커서를 비우도록 연동
- 피드백 저장 실패를 성공으로 표시하지 않도록 수정
- 입력창 높이에 따른 하단 여백 조정, 긴 카드 버튼 문구 줄바꿈
- 요청별·단계별 시간 측정 및 요청 식별자 연결

검색 함수 본문, 임베딩 모델, 랭킹 방식, 무료 한도 설정, 캐시 TTL/버전,
인덱서와 SQL 파일은 변경하지 않았습니다. 답변 품질 개선이나 실제 응답 속도
향상을 확인했다는 의미는 아닙니다.

## 검증 결과

- Python 자동 테스트: 24개 통과
- JavaScript 자동 테스트: 17개 통과
- 테스트에서는 .env 로드를 차단하고 실제 외부 API를 호출하지 않았습니다.
- 외부 AI 토큰 소비, Supabase 변경, Notion 쓰기 없이 검증했습니다.
- 기존 worker의 튜플 반환값, 각 처리 단계의 호출 횟수와 요청 ID 연결을 검증했습니다.
- 새 GitHub Actions 파일은 비밀키·DB 없이 테스트만 실행하도록 작성했습니다.
  현재 로컬에서만 작성했으며 원격 CI 성공을 의미하지 않습니다.

실행 명령:

```text
python -X utf8 -m unittest discover -s tests -p "test_*.py" -v
node --test tests/frontend.test.cjs
```

로컬 Python 3.14의 설치된 SDK에서 deprecation 경고가 발생했습니다.
테스트 실패는 없었지만 의존성 고정·Python 버전별 검증은 별도 작업입니다.

## 시간 로그 읽기

`[Performance]` 로그는 `request_id`, `stage`, `duration_ms`, `outcome`을 기록합니다.
`chat_total`은 HTTP 상태도 기록합니다.
추가한 시간 로그에는 질문·응답 본문·쿠키·키·예외 메시지를 포함하지 않습니다.
기존 애플리케이션 로그 전체를 정리한 것은 아닙니다.

단계: `cache_read`, `intent`, `keyword_expansion`, `embedding`,
`search`, `rerank`, `localization`, `cache_write`, `worker_total`, `chat_total`.

- `returned`는 함수가 반환됐다는 뜻이며, 답변의 정상 여부를 보증하지 않습니다.
- HTTP 200이어도 응답 본문의 status가 error일 수 있습니다.
- 검색 시간에는 임베딩 시간이 포함될 수 있어 단계 시간을 모두 더하면 안 됩니다.
- `X-Request-ID` 응답 헤더로 해당 요청의 시간 로그를 찾을 수 있습니다.
- `Server-Timing: chat_headers`는 응답 헤더 전송까지의 서버 시간입니다.
  `chat_total`은 ASGI 응답 전송까지이며 브라우저 렌더링·네트워크 시간은 제외합니다.
- Redis 작업은 요청 ID를 이어받지만 `chat_total`은 큐 접수 시간일 수 있습니다.
- 피드백의 10초 대기 제한은 이미 시작된 Notion 쓰기를 취소/롤백하지 않습니다.
  중복 저장을 피하려고 자동 재전송은 하지 않습니다.

## 운영 반영 전 남은 확인

computer-use 브라우저 초기화가 로컬 권한 오류로 실패했습니다.
따라서 실제 모바일 화면과 다크모드를 시각 검증했다고 간주하면 안 됩니다.
DOM 모의 테스트와 여백 계산 테스트는 실제 기기 검증을 대체하지 않습니다.

1. 360/390px 모바일 폭과 데스크톱에서 한국어·영어·베트남어·중국어 카드 확인
2. 다크모드에서 제목·본문·버튼 대비 확인
3. 여러 줄 입력, 가상 키보드, 추천 질문 접기/펼치기 시 하단 겹침 확인
4. 미리보기 환경에서 기존 캐시 적중과 더 보기 확인
5. 실제 로그를 통해 병목 구간 측정 후 별도로 최적화 판단

커밋·푸시·운영 배포 및 새 SQL 적용은 이번 작업에서 하지 않았습니다.
