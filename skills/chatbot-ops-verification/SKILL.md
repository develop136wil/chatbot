# 챗봇 운영 검증

검증한 범위와 미확인 범위를 구분해 한국어로 보고한다. 이 스킬을 선택한 사실이 배포,
SQL 실행, 운영 데이터 수정, 유료 서비스 사용을 승인하지는 않는다.

## 시작과 범위

- 현재 저장소의 `AGENTS.md`와 작업 상태를 확인한다. 원격 대상이
  `develop136wil/chatbot`인지 확인하고 다른 저장소(특히 supabase-keeper)로 범위를 넓히지 않는다.
- 기존 GitHub 연결·CLI·로컬 테스트를 우선한다. MCP 설치나 새 계정 연결은 전제 조건이 아니다.
- 과거 문서의 테스트 수·모델명·완료 기록을 현재 증거로 재사용하지 않는다.
  실행할 커밋의 코드와 workflow가 기준이다. 설명 문서와 구현이 다르면 차이를 보고한다.
- 키·토큰·환경변수 전체·사용자 질문 원문을 출력하지 않는다. 설정 비교는 필요한 호스트,
  모델 ID, 환경 이름 등 비밀이 아닌 값으로 제한한다.

## 작업에 맞는 절차만 읽기

- 예약 인덱싱 또는 로그 판정: [인덱싱 확인](references/indexing.md).
- 변경 검증, CI, Production 확인: [릴리스 확인](references/release.md).
- 모델·검색·다국어·캐시 확인: [답변 품질 확인](references/quality.md).

UI 변경이 포함될 때만 저장소의 `DESIGN.md`와 `docs/design-review-20260921.md`를 읽는다.
외부 디자인 스킬은 접근성·사용성 점검 기준일 뿐 기존 브랜드·국기·폰트·글라스 효과를
교체할 근거가 아니다. 설치된 DB·보안 스킬도 해당 검토가 요청 범위에 있을 때만 함께 사용한다.

## 권한과 중단 기준

- 상태 확인 요청에서는 코드/설정/SQL/키/운영 데이터를 바꾸거나 재실행·인덱싱·메일 발송을 하지 않는다.
- 실제 AI 호출은 무료 한도를 소비한다. 호출 대상·횟수 상한·가상 자료·부작용 차단을
  명시하고 요청 범위의 승인을 확인한다. 429/404/잘림이 나오면 검사 호출을 중단하고 보고한다.
- 모델명 자동 대체, 여러 키를 돌려 한도를 우회, 유료 자동 대체, 임베딩 차원 변경은 하지 않는다.
- CI나 조회가 실패하면 확인되지 않은 부분을 성공으로 추정하지 않는다. 새 권한이나 사용자 선택이
  필요하면 해당 부분만 중단한다. 작업을 완료하려고 운영 시스템을 임의로 복구하지 않는다.
- 기존 인덱싱 예약은 유지한다. 특정 실행을 기다리는 일만으로 새 자동화를 만들지 않는다.

## 보고

대상 저장소·환경·커밋·실행 링크, 실제 수행한 검사, 실패/보류, 미확인 범위,
사용자 조치가 필요한지 순서로 짧게 보고한다. HTTP 200, CI 성공, JSON 파싱,
번역 필드 존재만으로 전체 기능·정책 정확성·번역 품질을 보증하지 않는다.
