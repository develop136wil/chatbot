# 검색·캐시·다국어 품질

현재 모델·차원·호출 래퍼는 `utils.py`, `worker.py`, 관련 회귀 테스트에서 확인한다.
`docs/gemini-migration-20261111.md`는 당시 검사 범위 참고용이며 현재 배포나 계정 한도의 증거가 아니다.

## 검사 순서

1. 오프라인 회귀와 실제 SDK의 모의 HTTP 직렬화 검사를 먼저 수행한다.
2. 실제 호출이 필요한 이유, 공급자/모델, 최대 호출 수, 실패 시 중단 조건을 정한다.
   `FREE_TIER_ONLY`만으로 공급자의 결제 상태나 총비용이 보장되지 않는다.
3. 사용자 허용 범위 안에서 가상 자료만 사용한다. 기존 `scripts/gemini_migration_probe.py`를
   사용할 때는 코드의 모델 고정·7회 예산·키 순환/재시도 차단·DB/통계 차단이 현재 목적과 맞는지
   먼저 읽는다. `--live`는 자동 실행하지 않는다. 임의로 다른 공급자로 대체하지 않는다.
4. `ko/en/vi/zh/ja` 각각 금액·월령 경계·거주 조건·제외 조건·기간·출처 보존을 대조한다.
   응답 JSON 존재, STOP, HTTP 200과 의미 정확성을 구분한다. 한 사례의 합격을 전체 품질로 확대하지 않는다.

## 회귀에 포함할 사례

| 영역 | 확인할 동작 |
|---|---|
| 의도 | 서비스명이 다른 새 질문이 `show_more`로 잘못 처리되지 않음 |
| 카테고리 | 실제 DB 카테고리 또는 null로 정규화; 외국어 서비스명이 카테고리로 전달되지 않음 |
| 검색 | 실제 0건과 접근권한/인덱스 조회 불가를 구분; 오류를 단순 ‘검색 결과 없음’으로 숨기지 않음 |
| 순위 | 잘못된 번호·중복·잘림 시 기존 문서 누락 없이 안전하게 처리 |
| 캐시 | 동일 직전 질문의 적중, 언어별 분리, 문맥 후속 질문의 공유 캐시 회피 |
| 번역 | 모든 대상 언어의 제목/본문과 숫자·조건 보존; 한 언어 실패도 누락 없이 보고 |
| 추가 결과 | 명시적 ‘결과 더 보기’와 신규 질문 구분; 결과 중복/문맥 손실 확인 |

캐시 적중은 캐시 검증이지 새 모델 검증이 아니다. 실제 신규 경로를 확인하려고 운영 캐시를
삭제하거나 캐시 버전을 올리지 않는다. 가상·격리 검사로 해결되지 않으면 필요한 권한을 요청한다.
API 키나 실제 사용자 질문을 외부 평가 서비스에 보내지 않는다.

보고에서 오프라인/실제 API/브라우저/운영 E2E 검사와 원어민 검수 여부를 각각 구분한다.
